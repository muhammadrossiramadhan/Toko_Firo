Top 3 Prioritas Remediasi Utama

01
Proteksi Middleware Rute Admin & Kasir
Rute administrasi dan kasir dimuat di bootstrap/app.php hanya dengan grup middleware 'web'. Publik tanpa login dapat langsung mengakses dan mengeksekusi operasi pada seluruh endpoint panel admin dan kasir.
Rekomendasi Tindakan: Bungkus pemuatan rute admin dengan ['web', 'auth', 'role:ADMIN'] dan rute kasir dengan ['web', 'auth', 'role:KASIR'] di bootstrap/app.php.
02
Nonaktifkan Mode Debug & Amankan Rahasia
APP_DEBUG=true aktif di file .env, membocorkan seluruh kredensial database dan token Telegram saat terjadi exception. Kunci enkripsi backup memiliki string fallback hardcoded di kode sumber.
Rekomendasi Tindakan: Setel APP_DEBUG=false dan APP_ENV=production, lakukan rotasi (revoke) Bot Token Telegram, serta hapus string password statis di BackupService.php.
03
Penguatan Logika 2FA & Akun Nonaktif
Akun staf nonaktif masih dapat login penuh melewati OTP, counter verifikasi OTP rentan race condition, serta cooldown 90 detik dapat di-bypass dengan mengirim ulang permintaan POST ke /masuk.
Rekomendasi Tindakan: Validasi $user->status === 'AKTIF' di LoginController, gunakan operasi atomic Cache::increment, dan hash nilai OTP sebelum disimpan.

Audit Keamanan Injeksi SQL: NIHIL KERENTANAN (ZERO SQL INJECTION)

Audit menyeluruh terhadap seluruh lapisan akses basis data Toko Firo mengonfirmasi bahwa aplikasi menerapkan praktik pengikatan parameter (parameterized queries) secara disiplin dan konsisten. SEC-01 Kritis (CRITICAL) CWE-306 / CWE-284

Bypass Middleware Autentikasi dan Otorisasi pada Seluruh Rute Administrator

Lokasi Berkas: bootstrap/app.php (baris 16-18), routes/admin_*.php
Deskripsi & Dampak Kerentanan
Pada berkas bootstrap/app.php, seluruh rute administrasi (routes/admin_*.php) dimuat secara otomatis melalui callback 'then' dengan hanya menerapkan middleware grup 'web'. Berkas-berkas rute individual seperti admin_dashboard.php, admin_barang.php, admin_pembelian.php, admin_log.php, admin_toko.php, admin_batas_stok.php, admin_backup.php, dan admin_pengguna.php tidak mendefinisikan middleware 'auth' maupun 'role:ADMIN'. Akibatnya, seluruh modul administrasi toko terbuka untuk publik tanpa memerlukan proses login sama sekali. Penyerang eksternal dapat melihat laporan penjualan, memodifikasi master barang, mengubah harga produk, mengunduh salinan basis data, serta membuat atau menonaktifkan akun staf toko.
Langkah Reproduksi (Proof of Concept)
Terminal / HTTP Proof-of-Concept Bash 
# Pengujian akses langsung ke endpoint admin tanpa cookie sesi atau autentikasi:
curl -s -o /dev/null -w "HTTP Status: %{http_code}\n" http://localhost/admin/dashboard
curl -s -o /dev/null -w "HTTP Status: %{http_code}\n" http://localhost/admin/barang
curl -s -o /dev/null -w "HTTP Status: %{http_code}\n" http://localhost/admin/pengguna

# Hasil:
# HTTP Status: 200 (Seluruh halaman panel admin dapat diakses bebas tanpa pengalihan ke /masuk)
Rekomendasi Perbaikan & Solusi Kode
Solusi Perbaikan Kode PHP / Laravel 
// bootstrap/app.php
// Terapkan middleware 'auth' dan 'role:ADMIN' secara terisolasi saat memuat rute admin:
foreach (glob(base_path('routes/admin_*.php')) as $adminRoute) {
    Route::middleware(['web', 'auth', 'role:ADMIN'])->group($adminRoute);
}

SEC-04 Tinggi (HIGH) CWE-285 / CWE-613

Akun Staf Berstatus Nonaktif Masih Dapat Login dan Memperoleh Sesi Kerja

Lokasi Berkas: app/Http/Controllers/LoginController.php (baris 39-45), app/Http/Controllers/OtpController.php (baris 30-33)
Deskripsi & Dampak Kerentanan
Pada proses autentikasi dua langkah (2FA), method LoginController::authenticate hanya memverifikasi kesesuaian username dan pencocokan hash password (Hash::check) tanpa melakukan pengecekan atribut status akun. Demikian pula pada OtpController::verify, setelah kode verifikasi Telegram dinyatakan valid, sistem langsung mengeksekusi Auth::login($user). Akun staf atau kasir yang telah dinonaktifkan (status = 'NONAKTIF') oleh pemilik toko tetap dapat melewati login langkah pertama, menerima OTP, dan memperoleh akses penuh ke sistem.
Langkah Reproduksi (Proof of Concept)
Terminal / HTTP Proof-of-Concept Bash 
# Skenario pengujian:
# 1. Admin menonaktifkan staf via query/antarmuka: UPDATE pengguna SET status = 'NONAKTIF' WHERE username = 'kasir';
# 2. Pengguna 'kasir' melakukan POST ke /masuk dengan password yang valid;
# 3. Sistem menerima kredensial, membuat pending_2fa_user_id di sesi, dan mengirimkan kode OTP;
# 4. Pengguna memasukkan OTP di /verifikasi;
# 5. Sistem mengarahkan pengguna ke /kasir/dashboard dengan sesi aktif.
Rekomendasi Perbaikan & Solusi Kode
Solusi Perbaikan Kode PHP / Laravel 
// 1. Pada app/Http/Controllers/LoginController.php (authenticate):
if (! $user || ! Hash::check($request->password, $user->password)) {
    return back()->withErrors(['login' => 'Username atau password salah.'])->onlyInput('username');
}
if (strtoupper($user->status ?? '') === 'NONAKTIF') {
    return back()->withErrors(['login' => 'Akun Anda telah dinonaktifkan. Hubungi pengelola toko.'])->onlyInput('username');
}

// 2. Pada app/Http/Controllers/OtpController.php (verify):
if (strtoupper($user->status ?? '') === 'NONAKTIF') {
    $request->session()->forget('pending_2fa_user_id');
    return redirect()->route('login')->withErrors(['login' => 'Akun Anda tidak aktif.']);
}

SEC-06 Tinggi (HIGH) CWE-352 / CWE-652

Mutasi State Melalui HTTP GET Mengakibatkan Kerentanan Cross-Site Request Forgery (CSRF)

Lokasi Berkas: app/Http/Controllers/Admin/PenggunaController.php (baris 24-35), app/Http/Controllers/Admin/BatasStokController.php (baris 23-30)
Deskripsi & Dampak Kerentanan

SEC-07 Tinggi (HIGH) CWE-352

Pengecualian Validasi CSRF Terlalu Luas pada Pola Rute 'api/*'

Lokasi Berkas: bootstrap/app.php (baris 28-32)
Deskripsi & Dampak Kerentanan
Konfigurasi $middleware->validateCsrfTokens pada bootstrap/app.php mengecualikan pola wildcard 'api/*'. Pengecualian ini menonaktifkan seluruh mekanisme perlindungan token CSRF untuk seluruh rute API yang ada maupun yang akan ditambahkan di masa mendatang. Jika terdapat endpoint API yang mengandalkan sesi autentikasi berbasis cookie peramban, penyerang dapat mengeksekusi permintaan lintas-asal (cross-origin) dari peramban korban tanpa perlu menyertakan token CSRF yang valid.
Langkah Reproduksi (Proof of Concept)
Terminal / HTTP Proof-of-Concept Bash 
// Skrip berbahaya pada domain penyerang (attacker.com):
fetch('http://localhost/api/transaksi/simpan', {
    method: 'POST',
    credentials: 'include',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ item_id: 1, nominal: 500000 })
});
// Hasil: Permintaan diterima dan diproses server karena pola 'api/*' tidak diverifikasi oleh middleware CSRF.
Rekomendasi Perbaikan & Solusi Kode
Solusi Perbaikan Kode PHP / Laravel 
// bootstrap/app.php
// Batasi pengecualian token CSRF hanya pada rute webhook spesifik dari pihak ketiga:
$middleware->validateCsrfTokens(except: [
    'api/telegram/webhook',
]);
